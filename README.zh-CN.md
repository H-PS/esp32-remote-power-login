# WiFi 远程开机 + PIN 自动登录器

## 要解决什么问题

人在外面，笔记本关机或锁屏了，但你需要用上它。

| 场景 | 常见方案 | 为什么不行 |
|---|---|---|
| 笔记本已关机 | 网络唤醒（WoL） | 关机后网卡断电，无线 WoWLAN 通常不可靠 |
| 已开机但锁屏 | ToDesk / AnyDesk 无人值守、AutoHotkey、pynput | Windows 登录界面运行在**安全桌面（Secure Desktop）**上，用户会话尚未建立，**所有软件级按键注入都会被忽略** |
| 已开机但锁屏 | 带系统服务的商业远控软件 | 能用，但笨重、闭源、有隐私顾虑 |

**核心洞察**：Windows 登录界面**只认真键盘的输入**。所以要在这个环节做自动化，必须用**硬件 HID 设备** —— 而 ESP32-S3 恰好是干这个的完美选择（原生 USB-OTG，能把自己枚举成标准键盘）。

**另外**，如果机器是完全关机的，再多的 USB 魔法也没用 —— 所以我们再挂一个小舵机，**物理按压电源键**。

```
        手机（任何有网的地方）
                    │  MQTT
                    ▼
    ┌──────────────────────────────┐
    │           ESP32-S3           │
    │  ┌────────────┐ ┌─────────┐  │
    │  │ USB HID    │ │ 舵机    │  │
    │  │ 键盘       │ │ (GPIO4) │  │
    │  └─────┬──────┘ └────┬────┘  │
    └────────┼─────────────┼───────┘
             │ USB 数据线  │ 按压
             ▼             ▼
    ┌──────────────────────────────┐
    │   你的笔记本                 │
    │   [电源键]     [登录界面]    │
    └──────────────────────────────┘
```

一块板子，扮演两个角色：**一把键盘**和**一根手指**。

## 功能特性

- 🔌 **远程开机** —— 舵机物理按压电源键（机器完全关机时也能用）
- ⌨️ **自动输入 PIN** —— ESP32-S3 枚举为标准 USB HID 键盘，在登录界面自动键入 PIN
- ☁️ **云端控制** —— MQTT（巴法云），任何有网的地方都能控制；配套微信小程序操作流程
- 🌐 **局域网兜底** —— 内置 Web 服务器 + 浏览器界面（带口令保护），同一网络下可用
- 🔁 **自愈能力** —— WiFi 掉线自动重连 + MQTT 心跳，扛得住网络抖动
- 🧪 **内置自检** —— `test` 指令会把 PIN 打进记事本，用来区分「设备端问题」和「主机端问题」

## 接线

```
5V/2A 充电头 ──USB-C──▶ ESP "COM" 口          （供电，常年在线）
                          ├ 5V 排针 ──▶ 舵机红线
                          ├ GPIO4   ──▶ 舵机橙线   （PWM 信号）
                          └ GND     ──▶ 舵机棕线   （必须共地！）

ESP "OTG" 口 ──USB-C 数据线──▶ 笔记本 USB 口      （键盘信号）
```

- 舵机与 ESP 之间**必须共地**
- 舵机按压瞬间电流可达约 800 mA，5V/2A 供电有余量
- 板子上的两个 USB 口分别负责供电和数据，同时插着互不冲突

### ⚠️ `5Vin` 排针默认不通（要焊一个 0Ω）

在 **YD-ESP32-S3** 这类板子上，`5Vin` 排针**出厂并没有接到板内 5V**。从该脚到 5V 网络有两条并联路径：

```
5Vin ──┬──[ D3 二极管 ]──▶ 5V   单向（外部 → 板内），约 0.3V 压降     ← 出厂已装
       └──[ 0Ω 电阻  ]──▶ 5V   双向直连、无压降（丝印 "IN-OUT"）      ← 出厂未焊
```

所以默认状态下 `5Vin` 只能当**输入**（外接电源给板子供电）。想让它**输出** 5V，必须把那个 0Ω 的 `IN-OUT` 焊盘短路。

**厂商官方文档原文：**

> 5V-IN引脚默认是不向外供电，因为直接从核心板取电会影响ESP32的稳定运行，这样设计能够保护板子和保障板子稳定运行，如果需要5V供电，可以短接焊盘，可以对外输出5V

**焊上确实能用 —— 但千万不要用它给舵机供电。**

舵机是突发型负载：空闲 10~50 mA、转动 200~300 mA、**堵转 700 mA ~ 1 A**。焊上之后，这股电流要流经

```
充电头 → USB线 → D1二极管 → 板内5V网络 → 5Vin → 舵机
```

这条路上处处是电阻（线缆、连接器、**D1 的 0.3~0.5V 压降**、细铜箔）。按 `ΔV = I × R`，舵机一堵转就会把板内 5V 拉低 → ESP32-S3 的 3.3V LDO 跌破 dropout → **brownout 复位**。

最要命的是**复位的时机**：如果 ESP 恰好在 600 ms 的按压窗口里复位，舵机会在按压途中失去 PWM、僵在电源键上，而 ESP 重启并归位需要 3~5 秒 —— 这正好是多数笔记本**强制关机**的临界时间。你想让它开机，结果把它关机了。

**→ 给舵机一路独立的 5V：**

| 舵机线色 | 接到 |
|---|---|
| 橙（信号） | `GPIO14` |
| 红（电源） | **外接 5V 正极** —— 直接从充电头引，不走板子 |
| 棕（地） | 板子 `GND`，**同时**外接 5V 负极也必须接到板子 `GND`（共地是铁律） |

焊 `IN-OUT` 对**小负载**（OLED、传感器，<100 mA）完全没问题。

从充电头取 5V 的两个办法：剪一根废 USB 线（红 = 5V、黑 = GND），或买个几块钱的 USB 公头转接线端子。

### 舵机固定（凸轮装法）

1. 把舵机本体固定在电源键**正上方**，圆盘边缘对准按键
2. 圆盘边缘贴一小块硅胶垫 —— 这就是"压头"
3. 待机位 **10°**（离开按键），按压位 **95°**（按键压到底）。按你的机器实测微调 `SERVO_IDLE_DEG` / `SERVO_PRESS_DEG`
4. 这个运动**只有一个垂直自由度** —— 物理上不可能横扫

> 真正的风险不是"舵机还是电磁铁"，而是**力远超按键需求 + 没有行程限位**。笔记本电源键只需约 60~120 g 的力。

## 软件配置

### 1. Arduino IDE 设置

用开发板管理器安装 ESP32 板包，然后选择 **ESP32S3 Dev Module**，并把下面**每一项**都设好：

| 设置项 | 值 | 原因 |
|---|---|---|
| **USB Mode** | `USB-OTG (TinyUSB)` | 不选这个**不会**被识别为键盘 |
| **USB CDC On Boot** | `Enabled` | 选 `Disabled` 时 HID 不枚举（实测确认） |
| **Flash Size** | `16MB (128Mb)` | 匹配你的板子；默认 4MB 会烧不进去 |
| **PSRAM** | `OPI PSRAM` | 匹配你的板子 |
| **Partition Scheme** | `16M Flash (3MB APP/9.9MB FATFS)` | 匹配你的 Flash 布局 |

### 2. 安装库

- **ESP32Servo**（by Kevin Harrington）
- **PubSubClient**（by Nick O'Leary）

### 3. 填配置

**方式 A（推荐 —— 让凭据不进 git）**：把 `secrets.h.example` 复制成 `secrets.h`，在里面填你的真实值。`secrets.h` 已经在 `.gitignore` 里，永远不会被提交。

```cpp
// secrets.h
#define SECRET_WIFI_SSID  "你的WiFi名"
#define SECRET_WIFI_PASS  "你的WiFi密码"
#define SECRET_PIN_CODE   "123456"
#define SECRET_PAGE_TOKEN "换个口令"
#define SECRET_BEMFA_UID   "你的巴法云私钥"
#define SECRET_BEMFA_TOPIC "你的主题名"
#define SECRET_PC_MAC     "aabbccddeeff"
```

**方式 B（最简单）**：直接在 `wifi_pin_login.ino` 顶部的配置块里改。

```cpp
const char* WIFI_SSID = "你的WiFi名";
const char* WIFI_PASS = "你的WiFi密码";      // 开放网络填 ""
const char* PIN_CODE  = "123456";            // 你的 Windows PIN
const char* PAGE_TOKEN = "换个口令";          // 局域网网页口令

const char* BEMFA_UID   = "你的巴法云私钥";
const char* BEMFA_TOPIC = "你的主题名";       // 必须是 MQTT 类型的主题

const char* PC_MAC = "aabbccddeeff";         // 笔记本网卡 MAC（去冒号）
```

> 固件里用的是 `#if __has_include("secrets.h")` —— 有 `secrets.h` 就从里面取值，没有就退回用上面这些内联默认值。**两种方式都能编译。**

### 4. 烧录

数据线插 **`COM` 口**烧录，烧完把线换插 **`OTG` 口**运行。

ESP32-S3 的 GPIO19/20 有双重身份：烧录时它们是 USB-Serial-JTAG（一个 COM 口）；启动后变成 TinyUSB HID 键盘。**同一根线、同一个口，自己会变身。**

### 5. MQTT 云端配置（巴法云）

1. 注册巴法云 → 复制你的**私钥** → 填到 `BEMFA_UID`
2. 建主题 —— 看下面**「建主题的三个坑」**，**一次就建对**
3. 把主题名填到 `BEMFA_TOPIC`，重新烧录

**建主题的三个坑 —— 务必一次做对：**

**① 命名必须在「新建」那一刻填对，不要建完再改名**

主题的**名称**和**昵称**都必须在 `新建主题` 弹窗里就写成你最终想要的值（例如 `power003`）。

- ❌ 错误：建的时候随手取名（`test`、`power001`、`风扇`），事后再改名
- ✅ 正确：在"新建主题"弹窗里，**把名称和昵称都填成 `power003`**，一步到位

**为什么不能事后改**：巴法云要求**昵称 == 主题名**。改名操作很容易只改动其中一个，两者一旦不一致，就会出现**「伪在线」**状态 —— ESP 报告"订阅成功"，但控制台显示"订阅者离线"，消息被静默丢弃。这个故障模式**极难排查**。**建错了就删掉重建，比改名可靠得多。**

**② 必须建在「MQTT设备云」分页，类型选 MQTT**

- **TCP设备云**和**MQTT设备云**是**两个隔离空间**：
  - MQTT 协议（端口 **9501**）只能访问 **MQTT设备云**里的主题
  - TCP 协议（端口 **8344**）只能访问 **TCP设备云**里的主题
- 两者错配会产生同样的**「伪在线」**症状：订阅成功但收不到任何消息

**③ 主题类型要选「消息型」，不要选「开关型」**

| 主题类型 | 能转发什么 |
|---|---|
| **开关型** | **只有 `on` / `off`** —— 其他任何文本都被服务器静默忽略 |
| **消息型** | **任意文本**（`on`、`login`、`login1`、`test` …）✅ |

> 本项目有 5 条指令，所以**必须用消息型主题**。用开关型的话只有 `on`/`off` 生效，其他指令点了跟没点一样。

## 指令一览

| MQTT 消息 | 网页按钮 | 路由 | 动作 |
|---|---|---|---|
| `on` | 开机并自动登录 | `/servologin` | 舵机按电源键 → 等待 → 完整登录流程 |
| `off` | 只开机 | `/servopower` | 只按一次电源键 |
| `login` | 键入 PIN（完整流程） | `/login` | WOL → ESC → 回车 → PIN → 回车 |
| `login1` | 仅键入 PIN | `/login1` | PIN + 回车（**最稳，日常首选**） |
| `test` | 打字自检 | `/test` | 5 秒后把 PIN 打进记事本（排障用） |

### 该用哪条登录指令？

| 场景 | 用哪个 | 原因 |
|---|---|---|
| **锁屏**（`Win+L`，最常用） | `login1` | PIN 框本身已聚焦 —— 最快最稳，不碰任何其他东西 |
| **屏幕已关**（系统仍在运行） | `login` | 需要 ESC 点亮屏幕 + 回车聚焦输入框 |
| **已解锁，焦点在浏览器** | `login1` 或把 `LOGIN_SEND_PREAMBLE` 设 `0` | ⚠️ 此时 ESC/回车会误操作 |

> **一句话原则**：不确定就发 `login1`。它只做一件事 —— 打 PIN + 回车 —— 任何场景下都不会帮倒忙。

## 排障

### PIN 被多打了字符

**首先：检查你的测试场景。** 这个装置是为**锁屏状态**设计的。如果你在未锁屏时测试，焦点可能在浏览器里 —— 搜索框的自动补全会追加字符，而且回车触发的是一次搜索而不是提交 PIN。**测试前先用 `Win+L` 锁屏。**

**然后用 `test` 指令定位问题在哪一侧：**

1. 在笔记本上打开**记事本**并点进输入区
2. 网页点「打字自检」，或通过 MQTT 发 `test`
3. 你有 5 秒时间切到记事本，然后看出现什么

| 记事本里的结果 | 结论 | 怎么办 |
|---|---|---|
| 干净的 `123456`（6 个字符） | **设备端没问题** —— 多余字符来自主机侧 | 检查自动补全 / 输入法 / 焦点 |
| 也有多余字符 | 问题在发送端 | 把 `KEY_SETTLE_MS` 调到 80~100 |

**为什么固件要打得这么慢**：`Keyboard.write()` 会把按下和抬起两个 HID 报文**紧挨着发出、中间零间隔**。如果主机的 USB 轮询没采到中间态，down+up 会被合并成一次长按 → 触发**自动重复（auto-repeat）**。`typeString()` 改成每个字符 `按下 → 30ms → 抬起 → 60ms`，每次按键都是主机不会漏看的干净 down+up。放慢的节奏同时也降低了浏览器自动补全被触发的概率。

### 烧录失败（"No serial data received"）

- 确认线插在 **`COM` 口**，不是 `OTG`
- 换另一个 USB-C 口试（ESP32-S3 也能从 USB-Serial-JTAG 烧录，用 esptool 5.x 不需要按 BOOT）
- 有些板子需要：按住 **BOOT**，点一下 **RST**，松开 **BOOT**

### MQTT 连不上

固件会根据 PubSubClient 的状态码打印诊断提示：

- `state = -4` → TCP 超时（网络被拦）
- `state = -2` → TCP 连接失败（服务器拒连 / DNS 失败）
- `state = 5` → 未授权（检查你的 `BEMFA_UID`）

### 校园网老是掉线

很多校园网 Portal 会定时踢掉闲置客户端。固件每 10 秒自动重连一次 —— 你会在串口日志里看到 `[WiFi] dropped, reconnecting...`，这是正常的。

> **关于强制门户（Captive Portal）**：很多校园网**只劫持 HTTP 80 端口**（为了弹登录页），其他端口是放行的。如果你发现 MQTT 能通但 HTTP 不行，就是这个原因 —— **根本不需要过门户认证**。判断时请**直接对 MQTT broker 的端口做裸 TCP 连接测试**，不要从 HTTP 的行为去外推。

## 为什么不用网络唤醒（WoL）？

WoL 魔法包是**二层广播帧** —— 不需要 IP、不需要认证、不需要路由。但也正因如此，它对前提的要求非常硬：**收发双方必须在同一个广播域**。

| 方式 | 关机时能用吗 | 可靠性 |
|---|---|---|
| 无线 WoWLAN | ❌ | 只在网卡保持供电的睡眠状态下有效 —— 很多笔记本进 S3 就切断 WiFi 供电 |
| 有线 WoL | ⚠️ | 能用，**但要求 ESP 与目标机处于同一广播域** |
| **物理按压电源键（本项目）** | ✅ | **任何机器都能用，零配置，不受网络拓扑影响** |

### 我们真实踩到的失败

```
ESP 走校园 WiFi（网段 A）   ┐
                            ├─ 两个不同的 VLAN
笔记本走宿舍有线（网段 B）  ┘
```

受限广播 `255.255.255.255` **不会被三层设备转发**，魔法包根本到不了。**这不是网卡设置能救的** —— 是拓扑问题，不是驱动问题。

> 我们把 PC 侧的每一项都验证过了：`WakeOnMagicPacket = Enabled`、适配器已登记为唤醒源（`powercfg /devicequery wake_armed`）、关闭快速启动、**有线 + 无线两个 MAC 都发**、子网广播 + 定向单播都试了 —— 全部配置正确，全部无效。**别在这上面耗一个周末，先看拓扑。**

> **想让 WoL 真正可用？** 把 ESP 和目标机接到**同一台路由器**下面，让它们处于 `192.168.x.x` 同一网段，然后把 `ENABLE_WOL` 设为 `1`。

### 我们的替代方案：用锁屏代替睡眠

系统保持运行，ESP 键盘全程在线，一条 `login1` 就能登进去 —— **不需要 WoL、不需要舵机、不需要任何额外硬件**：

```powershell
powercfg /change standby-timeout-ac 0     # 插电：从不睡眠
powercfg /change standby-timeout-dc 0     # 电池：从不睡眠
```

再改一处：*控制面板 → 电源选项 → 选择关闭盖子的功能 → 不采取任何操作*（合盖记得注意散热）。

| 状态 | ESP 键盘能用吗 | 用哪条指令 |
|---|---|---|
| 屏幕已关（系统仍在运行） | ✅ | `login` |
| 锁屏（`Win+L`） | ✅ **最佳状态** | `login1` |
| 睡眠 / 休眠 | ❌ **必须避免 —— ESP 唤不醒它** | — |

## 项目结构
